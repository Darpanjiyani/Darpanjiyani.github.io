How I stopped my AI from inventing facts on my resume

A Claude skill that tailors my resume to a job in about 2 minutes, using only work I've actually done.

Darpan JiyaniNovember 20265 min readCode ↗

Why I built itTailoring by hand was slowing me down

I was applying to a lot of jobs every day, and every posting needed its own version of my resume. Rewriting it from scratch again and again was hard. On top of that, every edit meant fixing the formatting in Word. It took so much time that I couldn't apply to as many roles as I wanted.

So I built a Claude skill. I give it a job posting and my resume, and it returns a tailored one-page Word file plus a short report. I can run it in several chats at once, one per job, and do other work while it runs.

job posting + my resume → rank the job's top requirements → tailor from my Evidence Bank → Python checks → one-page .docx + report

The rule that mattersOnly what's on file. Numbers never change.

An AI that writes resumes has one dangerous habit: filling gaps with things that sound right. So the first rule was strict. The skill can only use facts from my Evidence Bank, a file with every project, metric and skill I can back up. It can reword, reorder and choose what to show, but it can't invent work or change a number.

Anything I haven't confirmed sits in [brackets], and bracketed text is never used. That turns "don't make things up" from a hope into a rule that both the model and a script can follow.

Don't just trust the promptCheck it in code

A prompt that says "don't invent facts" is a request, not a guarantee. So after every run, a Python script, check_resume.py, reads the tailored resume and compares every number, and the noun it counts, against my sources.

40+ ≠ 20+If the resume says "40+ engineers" and my sources say "20+ engineers", the checker flags it. The AI has to fix the flag and run the check again, or explain it in the report.

The same script checks that every GitHub link points to the right project. A second script flags stock AI words and repeated sentence shapes.

When it isn't sureLeave it out, and tell me

The skill never stops to ask questions halfway through. Anything uncertain goes on a Confirm Before Sending list instead: a missing metric, a derived number, or a conflict between my resume and the Evidence Bank.

In the sample run in my repo, for a fictional candidate, a dashboard's "hours saved per week" was still in brackets, so it stayed out of the resume and went on the list with a note: add the number to make that bullet stronger. A team project was skipped entirely because the candidate's own part wasn't filled in yet.

That last check is one of a few honesty rules written as fields on each project, not left to judgment. "My part" limits which team work I can describe as mine. "Tutorial-based" blocks any claim of original design. "Co-authors listed" blocks words like "solo".

The hardest partExactly one page, every time

When I started testing, the layout was the hardest part. My base resume fits exactly one page. But the tailored versions sometimes pushed lines onto a second page, and sometimes left an empty gap at the bottom. Neither was acceptable.

Two changes fixed it. First, the skill edits a copy of my Word file instead of rebuilding it, so it keeps the same styles, margins and small spacing tricks. Second, a page count wasn't a reliable test: the converter often lays out a Word file taller than Word does, so a one-page resume could look like two. So the checker renders the original and the tailored file the same way and compares the position of every line. If every line lands where it did before, the resume fills the page exactly like my original: nothing spills over, and no gap is left.

Sounding like mePlain, human wording

Recruiters can often feel when a resume was written by AI: the same stock words, every bullet shaped the same way, phrases copied straight from the posting. The skill bans a list of stock words, limits trailing "-ing" clauses, and requires every bullet to start with a different verb. Soft phrases from the posting, like "cross-functional collaboration", are shown through real facts instead of being pasted in.

What changedFrom 20 minutes to 2, with no formatting

Get the idea first, from your everyday work. Then make AI do the work.

There's a lot you can do with AI, but you need an idea of what you want it to do. Those ideas come on their own when you pay attention to your day-to-day tasks. This one came from doing the same tiring job every day. Find the task, see how AI can help, and then build it so you can trust what it gives back.
